# Публикация Этапа 1 на Render — пошагово

Инструкция рассчитана на то, что NBrain уже работает на Render по адресу
`https://app.nbrain-ts.org`. Ничего удалять и пересоздавать не нужно: код
обновляется, база остаётся на месте, ваш пароль продолжает работать.

Весь процесс — примерно 20 минут, из них 5 минут ожидания сборки.

---

## Шаг 0. Проверьте секрет сессии — иначе сервис не запустится

Это единственное изменение, которое может остановить деплой, поэтому проверьте
его **до** всего остального.

1. Откройте `https://dashboard.render.com/`, войдите.
2. Слева выберите сервис `nbrain`.
3. В левом меню сервиса нажмите **Environment**.
4. Найдите строку `NBRAIN_SESSION_SECRET` и нажмите на глаз или **Reveal**,
   чтобы увидеть значение.
5. Посчитайте длину. **Нужно не меньше 32 символов.**

Если короче — сгенерируйте новый. На своём компьютере в PowerShell:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Скопируйте вывод — он понадобится на шаге 3.

> Смена этого значения завершает все открытые сессии: после деплоя нужно будет
> войти заново. Данные при этом не теряются.

Заодно посмотрите, есть ли в списке переменная `NBRAIN_ADMIN_USERNAME`. Если её
нет, ваш логин сейчас — `admin`.

---

## Шаг 1. Убедитесь, что подключён Persistent Disk

Без диска Render стирает файловую систему при каждом деплое — вместе с базой,
книгами и аккаунтами.

1. В том же сервисе откройте в левом меню **Disks**.
2. Там должен быть диск, смонтированный по пути `/app/data`.

**Если диска нет — остановитесь и сначала создайте его**, иначе следующий
деплой сотрёт всё. Кнопка **Add Disk**, поле **Mount Path** — ровно `/app/data`,
размер от 1 ГБ. Диск доступен на платном типе сервиса.

Если диск есть — сделайте резервную копию прямо сейчас. В левом меню
**Shell**, затем:

```bash
python server.py backup
```

Команда напечатает путь вида `/app/data/backups/nbrain-20260806-140000.db`.
Копия останется на диске и переживёт деплой.

## Шаг 2. Отправьте новый код в GitHub

Render собирает образ из репозитория GitHub, а не из папки на вашем компьютере.
Пока код не в репозитории, обновление на Render не появится.

### Если вы работаете через GitHub Desktop

1. Откройте GitHub Desktop.
2. Слева вы увидите список изменённых файлов: `server.py`, `web/app.js`,
   `web/index.html`, `web/styles.css`, `Dockerfile`, `docker-compose.yml`,
   `.env.example`, `README.md`, `RENDER_DEPLOY.md`, `AUDIT.md`,
   `DEPLOY_STAGE1.md`, `tests/*`.
3. Внизу слева в поле **Summary** напишите: `Этап 1: аккаунты, безопасность, анкета`.
4. Нажмите **Commit to main**.
5. Нажмите **Push origin** вверху.

### Если вы работаете в командной строке

```powershell
cd C:\Users\USER\OneDrive\Desktop\nbrain_mvp
git status
git add .
git commit -m "Этап 1: аккаунты, безопасность, анкета"
git push
```

### Если репозиторий ещё не связан с папкой

`git status` ответит `fatal: not a git repository` — тогда загрузите файлы через
сайт: откройте свой репозиторий на GitHub → **Add file** → **Upload files** →
перетащите изменённые файлы → **Commit changes**.

> **Проверьте, что `.env` не попал в репозиторий.** В списке загружаемых файлов
> его быть не должно. Если он там есть — не загружайте и напишите мне, поменяем
> ключи. В `.gitignore` он уже исключён, но при загрузке через сайт правило не
> действует.

## Шаг 3. Обновите переменные окружения

1. В сервисе `nbrain` откройте **Environment** в левом меню.
2. Для каждой переменной ниже: если её нет — нажмите
   **+ Add Environment Variable** и добавьте; если есть — исправьте значение.

### Обязательные

| Переменная | Значение | Зачем |
|---|---|---|
| `NBRAIN_TRUST_FORWARDED_FOR` | `1` | Без неё все посетители считаются одним клиентом: один человек, подбирающий пароль, заблокирует вход всем остальным. На Render снаружи можно попасть только через прокси платформы, поэтому заголовку здесь можно доверять. |
| `NBRAIN_PUBLIC_URL` | `https://app.nbrain-ts.org` | Адрес в ссылках писем. Без неё ссылка подтверждения будет вести на `localhost`, и письмо станет бесполезным. |
| `NBRAIN_SESSION_SECRET` | новое значение из шага 0, если старое короче 32 символов | Сервис не стартует с коротким секретом. |
| `NBRAIN_ADMIN_USERNAME` | ваш логин, например `muhamed` | Только если хотите логин отличный от `admin`. **Работает лишь на пустой базе.** Ваш аккаунт уже создан, поэтому сейчас переменная ничего не изменит — логин остаётся прежним. |

### Проверьте, что уже стоят

`OPENAI_API_KEY`, `NBRAIN_AUTH_REQUIRED=1`, `NBRAIN_ADMIN_PASSWORD`,
`NBRAIN_SECURE_COOKIES=1`, `NBRAIN_DATA_DIR=/app/data`.

Переменную `PORT` создавать не нужно — Render выдаёт её сам.

### Почта — можно отложить

Без этих переменных регистрация и восстановление пароля работают, но письма не
отправляются: NBrain пишет их в журнал, и вы как администратор выдаёте ссылку
вручную. Добавьте, когда будет ящик для рассылки.

| Переменная | Пример |
|---|---|
| `NBRAIN_SMTP_HOST` | `smtp.gmail.com` |
| `NBRAIN_SMTP_PORT` | `587` |
| `NBRAIN_SMTP_USER` | `nbrain@nbrain-ts.org` |
| `NBRAIN_SMTP_PASSWORD` | пароль приложения, не основной пароль почты |
| `NBRAIN_SMTP_FROM` | `NBrain <nbrain@nbrain-ts.org>` |
| `NBRAIN_SMTP_SECURITY` | `starttls` |

Для Gmail нужен именно **пароль приложения**: включите двухфакторную защиту в
аккаунте Google, затем `myaccount.google.com` → **Безопасность** → **Пароли
приложений** → создайте пароль и вставьте его в `NBRAIN_SMTP_PASSWORD`.

### Если хотите закрыть регистрацию

Добавьте `NBRAIN_REGISTRATION_OPEN=0` — тогда вкладка «Регистрация» исчезнет и
аккаунты создаёте только вы.

3. Сохраните: нажмите стрелку рядом с кнопкой сохранения и выберите
   **Save, rebuild, and deploy**. Render соберёт образ заново — это нужно,
   потому что изменился `Dockerfile`.

## Шаг 4. Дождитесь сборки

1. Откройте **Logs** в левом меню.
2. Сборка идёт 3–6 минут: сначала установка шрифта и зависимостей, потом запуск.

В логе запуска должны появиться строки:

```
Applied migration 001_multi_user.
Applied migration 002_accounts.
NBrain MVP: http://0.0.0.0:10000
Outgoing mail: not configured (links go to the log)
```

`Applied migration 002_accounts` — главное подтверждение, что новые таблицы
созданы. При следующих перезапусках этих строк уже не будет: миграции
применяются один раз.

### Если сервис не поднялся

| Сообщение в логе | Что делать |
|---|---|
| `NBRAIN_SESSION_SECRET must be at least 32 characters long` | Вернитесь к шагу 0 и задайте секрет длиннее. |
| `For cloud access set NBRAIN_ADMIN_PASSWORD and NBRAIN_SESSION_SECRET` | Пропала одна из переменных, добавьте её заново. |
| `NBRAIN_AUTH_REQUIRED=0 leaves every request anonymous` | Поставьте `NBRAIN_AUTH_REQUIRED=1`. |
| `no such file or directory: /app/data` | Не подключён Persistent Disk, вернитесь к шагу 1. |

Откат: **Deploys** в левом меню → найдите предыдущий успешный деплой →
**Rollback to this deploy**. База при откате не страдает.

## Шаг 5. Проверьте, что всё работает

Откройте `https://app.nbrain-ts.org` в браузере.

1. **Вход.** Форма спрашивает логин и пароль. Введите свой логин (`admin` или
   тот, что вы задавали) и прежний пароль. Если меняли `NBRAIN_SESSION_SECRET`,
   старая вкладка попросит войти заново — это нормально.
2. **Данные на месте.** Раздел «Книги» — библиотека прежняя. Раздел «Память и
   действия» — заметки и действия прежние.
3. **Экспорт PDF.** Задайте вопрос в режиме Strategist и нажмите «Скачать PDF».
   Раньше в контейнере это всегда возвращало ошибку про шрифт; теперь должен
   скачаться файл. Это самая наглядная проверка, что новый образ собрался.
4. **Регистрация.** Откройте адрес в режиме инкогнито, вкладка «Регистрация»,
   заведите тестовый аккаунт на любой свой адрес. Войдите — откроется анкета.
   Заполните и убедитесь, что библиотека у нового аккаунта пустая: ваши книги
   ему не видны.
5. **Ссылка подтверждения без настроенной почты.** Вернитесь в свой
   администраторский аккаунт и откройте
   `https://app.nbrain-ts.org/api/admin/mail-log` — увидите текст письма со
   ссылкой. Скопируйте ссылку, откройте — адрес подтвердится.
6. **Удалите тестовый аккаунт.** «Профиль» → «Пользователи» → «Удалить».

---

## Шаг 6. Заведите привычку делать копии

Persistent Disk — это не резервная копия: он исчезнет вместе с сервисом. Раз в
неделю в **Shell**:

```bash
python server.py backup
ls -lh /app/data/backups
```

Файлы книг лежат отдельно, в `/app/data/uploads` — при переносе на другой хост
копируйте обе папки.

## Что изменится для вас после деплоя

- На странице входа появится поле логина и вкладка «Регистрация».
- Новые пользователи заводят аккаунты сами; у каждого своя библиотека, свои
  заметки и своя анкета. Чужие данные не видны никому, включая администратора.
- В разделе «Профиль» появятся смена пароля, выгрузка своих данных и удаление
  аккаунта, а у вас дополнительно — список пользователей.
- Дорогие операции ограничены квотой: 30 ответов модели и 120 поисков в час на
  аккаунт. Если вам этого мало, поднимите `NBRAIN_RATE_ANSWER` и
  `NBRAIN_RATE_SEARCH`.
- Ошибки теперь показываются всплывающими уведомлениями, а не прячутся в
  свёрнутых разделах.
