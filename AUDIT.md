# NBrain — аудит и план доработки до учебного продукта

Дата: 6 августа 2026. Состояние кода: `server.py` 2582 строки, `web/` 1203 строки,
`tests/` 195 проверок, деплой Docker + Render.

---

## 1. Что уже реализовано и работает

Проверено чтением кода и прогоном тестов; отмечено «проверено» только то, что
подтверждено тестом или ручным прогоном в этой сессии.

| Блок | Состояние |
|---|---|
| Аккаунты, вход, сессии | Работает. PBKDF2-SHA256 с индивидуальной солью, cookie подписана отпечатком хеша пароля, троттлинг подбора с блокировкой. Проверено 190 тестами. |
| Разделение данных между аккаунтами | Работает. Все выборки фильтруются по `user_id`; подставленный чужой `book_id` ничего не находит. Проверено тестами и через HTTP. |
| Загрузка книг PDF / EPUB / TXT | Работает. Стриминг на диск, защита от ZIP-бомб, проверка расширения, лимит 50 МБ. |
| Извлечение текста и разбиение на фрагменты | Работает. EPUB читается по `spine`, страницы нумеруются, чанки 450 слов с перекрытием 70. |
| Индексация | Работает. Фоновый пул из 2 воркеров, очередь 64, статус книги опрашивается интерфейсом. |
| Векторный поиск | Работает. Нормализованные float32-блобы, косинус = скалярное произведение, numpy с fallback на чистый Python. |
| Ответы LLM с источниками | Работает. Три режима (reader / thinker / strategist), подробный разбор книги, ссылки `[S n]` кликабельны и подсвечивают фрагмент. |
| Профиль директора | Работает. Имя, CliftonStrengths, цели, фокус — влияют на промпт. |
| Каталог развития из Excel | Работает. Импорт листа «Библиотека», фильтры, статусы чтения, рекомендации по простому скорингу. |
| Заметки-идеи и действия | Работает. Список, создание, закрытие действия. |
| Экспорт DOCX / PDF | DOCX работает. **PDF в Docker-образе не работает** — см. проблему P-07. |
| Деплой | `Dockerfile`, `docker-compose.yml`, `.dockerignore`, `RENDER_DEPLOY.md` на месте и согласованы; Persistent Disk и `NBRAIN_DATA_DIR` описаны. |

**Вывод:** ядро RAG — зрелое и аккуратно написанное. Параметризация SQL без
единой инъекции, двойная проверка path traversal, защита от ZIP-бомб,
stateless-сессии, осторожная работа с `X-Forwarded-For`. Это хорошая основа,
её не нужно переписывать.

## 3. Предлагаемые изменения

### 3.1 Архитектура

`server.py` — 2582 строки. Запрошенный учебный контур добавит ещё 3–4 тысячи.
Один файл станет неподдерживаемым, поэтому предлагаю разложить код на пакет,
**сохранив стек** (стандартная библиотека Python, SQLite, ванильный JS без сборки):

```
server.py              тонкая точка входа, «python server.py» работает как раньше
nbrain/
  config.py            переменные окружения в одном месте
  db.py                соединение, схема, миграции с версией
  security.py          пароли, сессии, троттлинг, CSRF, заголовки
  mail.py              отправка писем (SMTP) с журналом и dev-режимом
  llm.py               OpenAI и Claude, лимиты и бюджеты
  books/               загрузка, извлечение текста, индексация, поиск
  catalog/             каталог, внешние источники, лицензии
  learning/            планы, занятия, тесты, карточки, интервальное повторение
  progress/            прогресс чтения и обучения, статистика, достижения
  recommend/           рекомендации и объяснения
  api/                 маршруты, разбитые по разделам
  cli.py               команды терминала
web/
  js/                  ES-модули по разделам, без сборщика
```

Миграции — нумерованные шаги с таблицей `schema_migrations` и блокировкой, чтобы
два инстанса не мигрировали одновременно.

### 3.3 Принципиальные продуктовые решения

1. **Конспекты, тесты и карточки строятся только по реально доступному тексту.**
   Занятие привязано к диапазону фрагментов (`chunks`), в промпт уходит именно
   этот текст, у каждого тезиса — ссылка на страницу или главу. Если текста нет
   (книга под копирайтом, есть только описание) — занятие не создаётся, вместо
   него показывается карточка книги и легальные способы её получить.
2. **Каждый конспект помечается как вспомогательный материал**, а не замена книги —
   отдельной плашкой в интерфейсе и строкой в экспорте.
3. **Легальность источников** фиксируется в `book_sources`: `public_domain`,
   `open_license`, `user_upload`, `copyrighted_metadata_only`. Автоматически
   скачивается только первое и второе. Для третьего пользователь отвечает за
   свой файл (это фиксируется при загрузке). Для четвёртого — только описание,
   официальный фрагмент и ссылки на покупку, аренду и библиотеку.
4. **Внешние источники:** Gutendex (Project Gutenberg, общественное достояние),
   Open Library (метаданные и ссылки), Standard Ebooks (открытые лицензии).
   Все три бесплатны и легальны; ключи не нужны.
5. **Стоимость LLM ограничивается бюджетом на пользователя в сутки**: генерация
   занятия и тестов кешируется в БД и не пересоздаётся при каждом открытии.

### 3.4 План по этапам

**Этап 1 — фундамент и безопасность (критично для первой версии)**

1. Разложить код на пакет, ввести нумерованные миграции.
2. Закрыть S-01…S-05: обязательная авторизация по умолчанию, проверка
   `Content-Type` и `Origin`, ограничение частоты и бюджета на дорогих
   эндпоинтах, лимиты длины запросов, скрытие деталей ошибок внешних API.
3. Регистрация по email и паролю, подтверждение email, восстановление пароля,
   удаление аккаунта, экспорт своих данных, согласие на персонализацию.
4. Onboarding: интересы, навыки, прочитанные книги, желаемые книги, минуты в
   день, целевая дата, предпочитаемый формат.
5. Общие исправления интерфейса U-01, U-02, U-05, U-06 и глобальные уведомления.

**Этап 2 — учебный контур (ядро продукта)**

6. Читалка: постраничный просмотр извлечённого текста, позиция чтения,
   прогресс, закладки и заметки к фрагменту.
7. Генератор плана: разбиение книги на модули и занятия, календарь под
   доступное время и целевую дату, цель каждого занятия.
8. Занятие: краткое содержание, ключевые идеи, термины, цитаты, вопросы для
   самопроверки — всё со ссылками на страницы.
9. Тесты и карточки, интервальное повторение, адаптация темпа по результатам.
10. Статистика, прогресс, достижения, план занятий на неделю.

**Этап 3 — каталог, рекомендации, админка**

11. Каталог и поиск, интеграция Gutendex / Open Library / Standard Ebooks,
    лицензии и статусы авторских прав, легальные ссылки.
12. Рекомендации с объяснениями, скрытие книг, отключение персонализации.
13. Административная панель: каталог, источники, жалобы, модерация.
14. Режим ускоренного изучения как отдельный сценарий поверх занятий.

**Этап 4 — эксплуатация**

15. Резервное копирование, обработка `SIGTERM`, устойчивая очередь индексации,

## 4. Что критично для первой стабильной версии, а что можно позже

**Критично (без этого продукт не запускается):** этапы 1 и 2 целиком, из этапа 3 —
пункт 11 в минимальном виде (поиск по своей библиотеке + Project Gutenberg), из
этапа 4 — резервное копирование, `SIGTERM`, шрифт PDF.

**Можно во вторую очередь:** админка каталога и жалоб, Standard Ebooks и Open
Library, достижения, режим ускоренного изучения, устойчивая очередь индексации,
оптимизация памяти поиска, ES-модули на фронтенде.

**Честная оценка объёма.** Это не одна правка, а примерно 6–9 тысяч строк нового
кода и переработка интерфейса из 5 экранов в 15. За один заход добросовестно и с
проверкой такое не делается. Предлагаю идти этапами: после каждого этапа —
рабочее приложение, прогон тестов и отчёт о том, что действительно проверено.
